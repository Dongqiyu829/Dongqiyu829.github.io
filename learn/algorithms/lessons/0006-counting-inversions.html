Counting Inversions：
怎样跳过逐对枚举？

这次不只分析已有算法。我们给 Merge Sort 加一件事：看见一个小数时，一次数出一整段逆序对。

主线 20–25 分钟证明与代码可展开只攻克一次批量计数的理由
今天能做什么：解释并运用“右队首较小时，一次加上左侧剩余长度”，把二次枚举改成 Θ(n log n) 的逆序计数。

先回忆 1–3 分钟：为什么一层是线性的？

n=8 的 Merge Sort 完整合并层中，节点数翻倍、每个规模减半，为什么整层合并仍只写 8 个元素？如果每次合并顺便多做常数次算术，会改变整棵树的增长阶吗？先口头解释，不用返回旧课。

想过后核对

同层子数组互不重叠，规模总和为 n；2ᵈ×(n/2ᵈ)=n。如果每步合并只多做常数工作，局部仍是 Θ(m)，完整树仍是 Θ(n log n)。任意 n 最后层可能不满，第四课用完整层下界和每层上界处理。今天正要复用这套论证。

01 · 先设计一个保证不漏的算法

[2,4,1,3,5] 乱了多少对位置？

逆序对是下标对 (i,j)，满足 i<j 且 a[i]>a[j]。下标从 0 开始；相等不算。请先手写所有符合条件的位置对，不只是数值对。

写完核对三对

(0,2)：2>1；(1,2)：4>1；(1,3)：4>3，共 3 对。这里重复值也按不同位置区分，而严格大于才计数。

你来设计：怎样枚举每一对位置而不重复？先用两句话说，再看基线：

count = 0
for i = 0, …, n−1:
    for j = i+1, …, n−1:
        if a[i] > a[j]: count += 1

它检查 n(n−1)/2 对位置，时间 Θ(n²)，额外计数空间常数。第二课分析过同一串求和；现在我们要设计更快的方法，而不是只给基线起复杂度名字。

02 · 拆开的不是数值大小，而是原位置

每一对都属于三类之一

按原位置切成 [2,4] | [1,3,5]。任意 i<j 恰好属于：都在左半、都在右半、左侧一个且右侧一个。三类互不重叠且覆盖全部位置对。

递归分别解决左右两类，并让子调用同时返回计数与排好序的数组。剩下只数跨区间对。排序没有改变元素来自哪一半：左半每个元素在原数组的位置都早于右半每个元素，所以跨区间 i<j 已经成立，只需比较值。

上例两半本来各自有序，内部各 0 对；总数应是 0+0+跨区间数。若输入 [3,1,2]，左半 [3]、右半 [1,2]，仍要相加三类；不能只数某个子区间。

03 · 本课最重要的一步

右边的 1，为什么一下贡献两对？

现在 L=[2,4]、R=[1,3,5]，两者已经有序。i、j 指向各自尚未取出的第一个数。

R[j]=1 小于 L[i]=2，应该一次增加几对？

关键链条是：L 有序 → 每个剩余 L[t]≥L[i]>R[j] → 它们都与 R[j] 构成跨区间逆序对。剩余左侧长度为 len(L)−i。只加这个数，不再逐一比较它们；然后把 R[j] 写入合并结果并移动 j。

如果 L[i]>R[j]：
cross += len(L)−i；取走 R[j]

反之，若 L[i]≤R[j]，右侧剩余元素全部 ≥R[j]≥L[i]，所以 L[i] 与它们没有逆序对；取走左队首，增加 0。相等走左侧分支，正好保留严格大于的定义。

先预测取谁、加几对，再走一步

这里只演示两个有序子结果之间的跨区间计数。i、j 是排序后子数组的下标，不是原数组下标；累计量只包含跨区间对。

同一个 1 被取走后不会再计；下次取到右侧 3，只剩 L=[4]，再加 1。左侧已取走的 2 不该与 3 计数。这样批量处理，也没有重复。

04 · 把三个小算法拼起来

返回两个东西：排好序的数组与逆序数

sortCount(A):
    若长度 ≤ 1：返回 (A 的副本, 0)
    按原位置平分成两半
    (L, leftCount)   = sortCount(左半)
    (R, rightCount)  = sortCount(右半)
    (sorted, cross)  = mergeCount(L, R)
    返回 (sorted, leftCount + rightCount + cross)

只返回计数不够：父调用还要利用子数组的有序性，才能再次批量计数。现在你设计的子问题契约是“既排序、又计数”。

严格证明：为什么不漏计、不重计？

mergeCount 的局部不变量：输出前缀有序，已消费的元素恰好是这个前缀；尚未处理的潜在跨区间对只涉及两个未消费后缀。取左元素时，它≤所有未消费右元素，没有新对；与先前取走的右元素形成的逆序已经在当时计过。

取右元素时，若左侧非空且右队首更小，它与所有且仅与当前未消费的左元素形成尚未计入的逆序，数量 len(L)−i。已消费的左元素不大于当前右元素（它们当时不大于彼时右队首），不会漏计。每个右元素只被消费一次，且一个跨区间对仅在其右元素被取走时计入，因此恰好一次。一边用尽后直接复制，新增 0；指针前进保证结束。

对数组长度归纳：长度≤1 无逆序。更长数组的两半更短，由归纳假设各自返回正确内部计数及有序数组。局部论证给出准确跨区间数与有序合并结果；三类位置对不交且穷尽，所以相加恰为总逆序数，并返回正确排序结果。子问题规模严格减小，整个算法终止。

严格分析：批量计数为什么不又花线性一段？

一次合并总长 m，指针总共前进 m 次；每步的比较、下标更新、len(L)−i 与累加按单位代价为常数。写出左侧剩余长度无需逐个列出元素，所以非递归工作 Θ(m)。数组切分、分配与复制也在线性范围内。

对 n≥2，树与第四课相同。深度 0 到 ⌊log₂n⌋−1 都是完整合并层，每层写 n 次，给下界；每层合并长度之和≤n，至多 ⌈log₂n⌉ 个合并层，给上界。故合并写入 W 满足 n⌊log₂n⌋≤W≤n⌈log₂n⌉，包括常数边界开销后 T=Θ(n log n)。无需假定所有层都满；n=0、1 为 Θ(1)。

本课按整数比较、索引和计数算术为单位代价；C++ 用 long long 计数，Python 用整数。逆序数最多 n(n−1)/2，不能因元素值装得进 int 就用 int 存计数。顺序递归、复制数组的实现峰值辅助空间 Θ(n)，栈自身 Θ(log n)，与累计写入次数不同。

主线结论：合并时每次只加一个长度，仍是线性合并；把同一件线性工作放回均衡树，就从二次枚举降到 Θ(n log n)。

独立迁移：把相等也走右侧，会发生什么？

提示

长度 1 不会发生合并；长度 2 能否放两个相等元素？原定义是 >，不是 ≥。

独立作答后核对

[1,1] 即为最小反例：正确 0，错误分支加 1。右队首与左队首相等，无法推出所有剩余左元素都严格大于它。应在 L[i]≤R[j] 时取左、不加；只在 R[j]<L[i] 时计入剩余长度。

[2,2,1] 正确 2：两个位置上的 2 各与 1 构成逆序，两个 2 彼此不构成。错误写法会把相等的一对也算入，得到 3。不要把它理解成“重复值都不计”：重复的大数与后面的小数仍各有一对。

#include <algorithm>
#include <iostream>
#include <stdexcept>
#include <vector>
using namespace std;
struct Result { vector<int> values; long long count; };
Result sortCount(const vector<int>& a) {
    if (a.size() <= 1) return {a, 0};
    size_t mid = a.size()/2;
    auto left = sortCount(vector<int>(a.begin(),a.begin()+mid));
    auto right = sortCount(vector<int>(a.begin()+mid,a.end()));
    long long answer = left.count + right.count;
    vector<int> out; out.reserve(a.size());
    size_t i=0,j=0;
    while (i<left.values.size() && j<right.values.size()) {
        if (left.values[i] <= right.values[j]) out.push_back(left.values[i++]);
        else {
            throw runtime_error("TODO: 一次计入左侧剩余元素");
            out.push_back(right.values[j++]);
        }
    }
    while (i<left.values.size()) out.push_back(left.values[i++]);
    while (j<right.values.size()) out.push_back(right.values[j++]);
    return {out,answer};
}
int main() {
    vector<vector<int>> tests={{},{7},{2,4,1,3,5},{1,2,3,4,5},{5,4,3,2,1},{2,2,1},{-1,-3,-2},{4,1,3,2}};
    long long expected[]={0,0,3,0,10,2,2,4};
    int passed=0;
    for(int k=0;k<8;++k) {
        auto original=tests[k],sorted=original; sort(sorted.begin(),sorted.end());
        try {
            auto actual=sortCount(tests[k]);
            bool ok=actual.count==expected[k] && actual.values==sorted && tests[k]==original;
            passed+=ok;
            cout<<(ok?"PASS":"FAIL")<<" n="<<tests[k].size()<<" expected="<<expected[k]
                <<" got="<<actual.count<<" sorted=[";
            for(int v:actual.values) cout<<v<<' ';
            cout<<"]"<<endl;
        } catch(const exception& error) { cout<<"FAIL error="<<error.what()<<endl; }
    }
    cout<<passed<<"/8 passed"<<endl;
}

Python

def sort_count(a):
    if len(a) <= 1:
        return a[:], 0
    mid = len(a)//2
    left, left_count = sort_count(a[:mid])
    right, right_count = sort_count(a[mid:])
    answer = left_count + right_count
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i])
            i += 1
        else:
            raise NotImplementedError("TODO: 一次计入左侧剩余元素")
            out.append(right[j])
            j += 1
    while i < len(left):
        out.append(left[i])
        i += 1
    while j < len(right):
        out.append(right[j])
        j += 1
    return out, answer
