01 · 把一个大任务变小

要给这八个数排序，你会怎么拆？

第一课的二分搜索要求输入有序。现在输入是 [7,2,5,1,6,3,8,4]，我们要得到 [1,2,3,4,5,6,7,8]，每个元素都保留，允许重复值。

把它切成左右两半：[7,2,5,1] 和 [6,3,8,4]。这还没有排序！它只是给出两个子问题：分别把左半和右半排好。

假设两半已经排成 [1,2,5,7] 与 [3,4,6,8]，接下来应该？

这就是分治的一个例子：拆成更小的同类任务，解决它们，再把解合起来。选两半，是因为它们都显著变小，而且两个有序序列能够快速合并。

递归调用不是凭空获得答案

递归调用就是一个函数再次调用自己，但这次处理更小的输入。父调用先暂停，等子调用返回有序结果，再继续。每次调用有自己的数组、进度和返回值。

sort(A):
    如果长度 ≤ 1：直接返回 A
    从中间切成 L、R
    left  = sort(L)   // 等左边排好再返回
    right = sort(R)   // 再等右边排好
    返回 merge(left, right)

跟着最左边走：[7,2,5,1,6,3,8,4] → [7,2,5,1] → [7,2] → [7]。一个数本来就有序，于是 [7] 返回；[2] 也返回，合成 [2,7]。同理 [5] 与 [1] 合成 [1,5]；再合成 [1,2,5,7]。右半最终返回 [3,4,6,8]。

为什么会结束？长度 m≥2 时，两半长度分别为 ⌊m/2⌋、⌈m/2⌉，都小于 m。到 0 或 1 就直接返回，叫递归边界（base case）。⌊ ⌋ 表示向下取整，⌈ ⌉ 表示向上取整。

从叶子向上核对完整返回过程
  1. [7]+[2] → [2,7]；[5]+[1] → [1,5]；[6]+[3] → [3,6]；[8]+[4] → [4,8]。
  2. [2,7]+[1,5] → [1,2,5,7]；[3,6]+[4,8] → [3,4,6,8]。
  3. [1,2,5,7]+[3,4,6,8] → [1,2,3,4,5,6,7,8]。

merge：只比较两个队首

现在合并 L=[1,2,5,7]、R=[3,4,6,8]。用两个下标 i、j 指向各自尚未取出的第一个数。每次把较小队首写入新数组，再移动那一侧下标；相等时取左边即可。

  1. 1 与 3 比，取 1；再以 2 与 3 比，取 2。输出 [1,2]。
  2. 5 与 3 比，取 3；5 与 4 比，取 4。输出 [1,2,3,4]。
  3. 继续取 5、6、7；左半用尽，把右半剩下的 8 接上。

先自己解释：为什么不用把左边每个数与右边每个数比较？

用有序性检查理由

各侧队首是该侧剩余元素的最小值。因此两队首中较小的，就是所有剩余元素的最小值；取走它后，原性质仍成立。一侧用尽后，另一侧的剩余部分可直接依次写入。

合并总长为 m 的两段，每个元素恰好写入新数组一次，所以恰好 m 次写入。比较次数可能不足 m，但最多 m−1 次；每次指针操作为常数。因此一次 merge 的时间是 Θ(m)，不是 Θ(m²)。

严格正确性：为什么整套递归排序成立？

对长度作强归纳。长度≤1 时已排好且元素不变。假设所有更短输入都能正确排序；长度 m≥2 时两子问题都更短，因此分别返回保留原元素的有序数组。merge 每步选出剩余全局最小值，输出前缀一直有序且不丢不重；最终输出所有 m 个元素。因此整个结果有序且恰好是原数组的一个排列。长度严格下降也保证终止。

02 · 同一层一起记账

子问题翻倍，单个问题减半

第三课先列每轮工作再求和；这次先列每层的工作。每个节点代表一次 sort 调用；两个子节点是它切出的左右半。深度 0 是最初调用。

给一个节点计费时，只计它自己的 merge，不把子调用的时间再记进去，否则重复收费。树按深度排开是为了算账；真实程序通常先走完左子树、再走右子树，合并从底部返回，并非同层同时执行。

n=8 时，深度 1 有两个规模为 4 的调用。本层合并共写入？

每次展开一层，先预测再核对

“根L / 根R”表示父节点的左 / 右子调用，继续添加 L/R 表示路径。节点显示实际子数组、规模与自身合并写入数。换成 n=5，观察哪些层不再满。

    n=8 的完整账本（叶子不 merge）：

    深度调用数各自规模本层写入
    0181×8=8
    1242×4=8
    2424×2=8
    3810，直接返回

    因此合并写入总量是 8+8+8=24。叶子的 0 指合并写入为 0，不是函数调用免费；八个叶子另有 Θ(8) 控制开销。

    03 · 从八个数推到 n 个数

    n 的工作，重复了多少层？

    先设 n=2ᵏ。在深度 d<k，有 2ᵈ 个规模为 n/2ᵈ 的子问题。因此这一层：

    2ᵈ × (n / 2ᵈ) = n 次 merge 写入

    从 n 减半 k 次才变成 1，所以 k=log₂ n。这里 log₂ n 的意思是“2 的几次方等于 n”；例如 log₂8=3。深度 0 到 k−1 共 k 个合并层，深度 k 为叶子。总层数 k+1，合并层数 k，别差一层。

    W(n) = n + n + ⋯ + n = n log₂ n
    每层 Θ(n) × log₂ n 个合并层 → Θ(n log n)

    第三课的各轮是 1、2、4、…，总和线性；这里各层都是 n，因此对数个 n 要相加。这一次“层数乘每层”是紧确计数，而不是用最大层代替所有较小层。

    本课讨论的是总运行时间。以新数组完成每次 merge 的普通版本，即便输入已经有序也照常合并；不加入“已有序就跳过”的优化。

    严格论证：任意整数 n 与单位代价模型

    模型与输入：n 是元素个数，n≥0；整数比较、索引、一次元素写入按常数时间计。C++ 动态数组追加按摊还常数，Python 列表切片按长度计。下面程序的切分、分配、复制均包含在总时间中。分析的是可表示输入在该模型下的渐进增长，不是无穷精度整数的位复杂度。

    定义 W(n) 为所有 merge 向新输出数组的写入总数。W(0)=W(1)=0；长度 m≥2 的一个调用贡献 m，子问题大小为 ⌊m/2⌋、⌈m/2⌉。所以现在才可把刚才的过程记成 W(m)=W(⌊m/2⌋)+W(⌈m/2⌉)+m。

    树高：n≥2，令 h=⌊log₂n⌋，H=⌈log₂n⌉。深度 d 的已有节点大小介于 ⌊n/2ᵈ⌋ 与 ⌈n/2ᵈ⌉，由每次均分归纳得到。因而最大深度为 H；至少要走 H 次才可让最大子问题降到 1，至多 H 次也一定到 1。

    每层上界：同层子数组互不相交，所有待合并节点的长度总和至多 n，所以每个深度的 merge 写入≤n；至多 H 个合并层，故 W(n)≤nH。

    匹配下界：对每个 d=0,…,h−1，⌊n/2ᵈ⌋≥2，尚无分支停在叶子。该层所有节点都合并，并完整划分原数组，长度总和恰为 n。因此前 h 层已经贡献 nh，W(n)≥nh。最后一个不满的合并层可少于 n，例如 n=5 时为 2；不能声称任意 n 的所有合并层都恰为 n。

    n⌊log₂n⌋ ≤ W(n) ≤ n⌈log₂n⌉
    对 n≥2：½ n log₂n ≤ W(n) ≤ 2n log₂n

    最后一步用到对 x≥1：⌊x⌋≥x/2 且 ⌈x⌉≤2x。这给出固定常数的双侧界，不只是几个样例。

    从写入到时间：一次规模 m 的内部调用，除子递归外只做 O(m) 的切分、合并、循环控制和分配；至少有 m 次写入。n≥1 时恰有 n 个单元素叶子、n−1 个内部节点，故调用数为 2n−1。存在固定 a,b>0，使 a(W(n)+n) ≤ T(n) ≤ b(W(n)+n)。结合上式，所有输入排列均有 T(n)=Θ(n log n)，n=0、1 为 Θ(1)。这里没有借助任何通用递推定理。

#include <stdexcept>
#include <vector>
using namespace std;

struct Stats { long long writes = 0; int maxDepth = 0; };

vector<int> mergeSort(const vector<int>& a, Stats& stats, int depth = 0) {
    stats.maxDepth = max(stats.maxDepth, depth);
    if (a.size() <= 1) return a;
    size_t middle = a.size() / 2;
    auto left = mergeSort(vector<int>(a.begin(), a.begin() + middle), stats, depth + 1);
    auto right = mergeSort(vector<int>(a.begin() + middle, a.end()), stats, depth + 1);
    vector<int> out;
    out.reserve(a.size());
    size_t i = 0, j = 0;
    while (i < left.size() && j < right.size()) {
        throw runtime_error("TODO: 选择较小的队首");
        ++stats.writes;
    }
    while (i < left.size()) { out.push_back(left[i++]); ++stats.writes; }
    while (j < right.size()) { out.push_back(right[j++]); ++stats.writes; }
    return out;
}

int main() {
    vector<vector<int>> tests = {
        {}, {7}, {2,1}, {2,2,2,2},
        {-2,3,-2,0,1}, {1,2,3,4,5}, {6,5,4,3,2,1},
        {7,2,5,1,6,3,8,4}

    stats["max_depth"] = max(stats["max_depth"], depth)
    if len(a) <= 1:
        return a[:]
    middle = len(a) // 2
    left = merge_sort(a[:middle], stats, depth + 1)
    right = merge_sort(a[middle:], stats, depth + 1)

    可选进阶 · 为什么“比较两边”没有变成普通二重循环？

    merge 的每次队首比较都会永久取走至少一个元素，两个下标总共只前进 m 次，不会把每个元素与另一边所有元素比较。单次比较次数至多 m−1。

    对本课均衡拆分的两段，长度各至少 ⌊m/2⌋，至少比较 ⌊m/2⌋ 次才可能耗尽一侧；因此每个内部节点的比较数为 Θ(m)。沿同一棵树求和，整体比较次数也为 Θ(n log n)。第二课逐对比较枚举所有元素对，才会得到 Θ(n²)。两者的增长阶来自实际枚举了什么，不能凭代码有几个循环判断。

    今天的一句话：先数每个节点自身的工作，再按层求和；均衡拆分让单层工作为线性、合并层数为对数。遇到不均衡拆分，要重新画树。
