COMP3711H Prep · Lesson 02

渐进分析不是数循环

今天只练一项能力：指定清楚 cost model，然后从实际执行的操作数证明 tight bound。不靠“看到两层循环就喊 n²”。

约 25 分钟推导 + 交互实验衔接第 1 课的 Θ(log n)
本课胜利条件：拿到一个循环，你能依次说清输入规模、单位代价、操作总次数、上界和匹配的下界；最后正确写出 Θ，而不仅仅给一个宽松的 O。

0 · 一个容易误判的程序

先假设 n ≥ 1，而 work() 每执行一次只做常数时间的工作。

for (i = 1; i < n; i *= 2):
    for (j = 0; j < i; j++):
        work()

外层执行 Θ(log n) 轮，内层最多执行 O(n) 次。于是有人直接得出 Θ(n log n)。

你觉得这份分析最大的漏洞在哪里？

1 · 先约定什么叫“时间”

我们使用简化的 unit-cost RAM model：一个机器字范围内的比较、加减、赋值、数组访问等基本操作花费常数时间；这里假定 work() 自身也花常数时间。暂时不计缓存、I/O 和大整数位运算。

输入规模是 n，运行时间 T(n) 则是这些基本操作的总成本。先数 work() 是一个方便的起点，但完整分析还需确认循环控制的开销不会改变渐进阶。

关键区分：输入大小、基本操作、分析情形（最好／最坏／期望）必须说明。缺少任意一个，“这个算法是 Θ(n)”都可能是不完整的陈述。

2 · 别乘最大值；把每轮加起来

取 n = 16。外层依次取 i = 1, 2, 4, 8，对应的 work() 执行次数分别为 1, 2, 4, 8。

W(16) = 1 + 2 + 4 + 8 = 15

推广到 n = 2ᵏ，共有 k 个外层值，几何级数给出：

W(n) = ∑(r=0…k−1) 2ʳ = 2ᵏ − 1 = n − 1

所以即使外层有 log₂n 轮，实际做的主要工作仍只有线性数量。下面的实验会让差异更直观。

交互实验：输入规模 n 选择为 2 的幂，分别比较“内层增长”和“内层逐行增长”的两种程序。

展开：两个程序逐行究竟做了什么？ 
// 倍增：1 + 2 + 4 + … = Θ(n)
for (i = 1; i < n; i *= 2):
    for (j = 0; j < i; j++):
        work()

// 逐行：1 + 2 + … + n = Θ(n²)
for (i = 1; i <= n; i++):
    for (j = 0; j < i; j++):
        work()

3 · 当 n 不是 2 的幂，证明还成立吗？

设 k = ⌈log₂ n⌉（对 n = 1 取 k = 0）。外层取到 2⁰, 2¹, …, 2ᵏ⁻¹，于是 W(n) = 2ᵏ − 1。

因为 n ≤ 2ᵏ < 2n（n ≥ 2），有：

n − 1 ≤ W(n) < 2n − 1

对充分大的 n，左边至少是 n/2，右边小于 2n。因此 W(n) = Θ(n)。外层控制开销是 O(log n)，内层控制开销与 W(n) 同阶，且每次 work() 至少花常数时间，所以整个程序也是 Θ(n)。

这一段就是严格分析常见的逻辑链：精确计数 → 两侧夹住 → tight bound。

4 · O、Ω、Θ 不是什么“不同速度”

在 T(n) ≥ 0 且 f(n) > 0 的充分大输入上，它们说的是三种数学关系：

记号形式化含义（存在常数 c>0、n₀）直觉
O(f(n))所有 n ≥ n₀：T(n) ≤ c·f(n)上界
Ω(f(n))所有 n ≥ n₀：T(n) ≥ c·f(n)下界
Θ(f(n))同时满足 O(f(n)) 与 Ω(f(n))匹配的双侧界

例如 T(n) = 3n² + 7n + 5，对所有 n ≥ 1：

3n² ≤ T(n) ≤ 15n² ⇒ T(n) = Θ(n²)

这个算法也属于 O(n³)，甚至 O(2ⁿ)；但是后两者都不是 tight bound。写 O(n²) 并不自动代表你证明了 Θ(n²)。

如果已知某算法最坏情况下 T(n)=5n+4，下面哪句话正确？

5 · 另一个常见陷阱：两个循环确实可能是二次

for (i = 1; i <= n; i++):
    for (j = 0; j < i; j++):
        work()

这里每次内层执行 i 次，故

W(n) = 1 + 2 + ⋯ + n = n(n+1)/2

对 n ≥ 1，n²/2 ≤ W(n) ≤ n²，所以 Θ(n²)。注意区别：不是“两层循环导致二次”，而是这两个循环的实际执行次数之和确实呈二次增长。

6 · 别忘记你在分析哪一种输入

顺序查找一个元素，若它恰好位于数组第一项，一次比较就结束：最好情况 Θ(1)。若它不存在，必须检查所有 n 项：最坏情况 Θ(n)。

因此“顺序查找是 Θ(n)”通常隐含了“以 n 为规模的最坏情况”。若不说明分析情形，一个算法甚至可能没有唯一的运行时间函数 T(n)。

小结：先指定「度量什么、对谁度量」，再写渐进符号；把 worst-case、best-case、expected-case 混在一起，会让形式正确的不等式回答错误的问题。

7 · 迁移题：再遇到两层循环

这一次外层仍然倍增，但内层工作量却随着 i 增大而缩小。取整数 n ≥ 1：

for (i = 1; i <= n; i *= 2):
    for (j = 1; j <= n / i; j++):  // 整数除法
        work()

先独立回答：① 对 n = 8，work() 共执行几次？② 对任意 n，请写出求和式；③ 给出一个下界和一个上界，并推出 tight bound。

不要直接把 log n 乘上 n；想想每轮的实际代价。

① 8 + 4 + 2 + 1 = 15。② 操作次数为 W(n)=∑(r=0…⌊log₂n⌋) ⌊n/2ʳ⌋。③ 首项已给出 W(n) ≥ n，而 W(n) ≤ n(1+1/2+1/4+⋯) < 2n，所以 W(n) = Θ(n)；控制开销不会改变总阶。

有趣的是：这一题虽然和第 0 节程序完全不同，但时间复杂度相同。算法分析关心的是求和结构，而不是代码表面长相。

课后答题卡：四行完成 tight analysis

1 · Model

n 是什么？每次基本操作的成本是什么？分析哪种情况？

2 · Count

写出总工作次数 W(n) 的和式或递推式，而不是数循环层数。

3 · Bounds

找常数 c₁,c₂>0，夹住工作量，且确认控制开销同阶或更低。

最后写出明确结论：T(n) = Θ(f(n))，并指出上下界适用的 n ≥ n₀。这是之后分析 Merge Sort、Heap、图算法时反复要用的基本动作。
