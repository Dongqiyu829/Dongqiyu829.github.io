二分搜索：
为什么这半边可以丢？

从一个数组开始。先想清要找什么，再解释每一次排除，最后把这些理由写成代码。

主线约 20 分钟先手算 · 再演示 · 再编码证明与进阶可展开
今天的目标：在一个已排好序的数组中，找到第一个大于或等于 x 的位置，并解释为什么两种情况分别更新 lo = mid + 1 和 hi = mid。

只需会读数组和 while 循环。下标、区间和“不变量”都会在用到时解释；不用预先认识复杂度符号。

01 · 先把任务看清楚

找的是位置，而且必须是第一个

看这个已经从小到大排好序的数组，允许重复值：

下标元素
01
12
22
34
47

下标就是位置编号，从 0 开始。因此 a[1] = 2 表示“1 号位置放着数字 2”。数组长度 n = 5，最后一个元素的下标是 4。

令 x = 2。我们要返回第一个大于或等于 2 的元素的下标。这个任务叫 lower_bound。

先自己找：应该返回哪个下标？

再约定一个边界：如果没有任何元素满足条件，就返回 n。例如找 x = 9 时返回 5。5 是“没有找到”的返回位置，不是可以读取的 a[5]。空数组同样返回它的长度 0。

02 · 一次比较能告诉我们多少？

数组有序，所以不用逐个检查

从左到右检查当然可以。二分搜索则先看中间：上例的中间位置是 mid = 2，值为 a[2] = 2。

停一下：它已经满足 a[mid] ≥ x，可以直接返回 2 吗？先用上一题的答案反驳一下。

想过之后，看这次能确定什么

不能直接返回，因为左边的下标 1 也满足条件，而且更早。我们可以确定：下标 2 以及更右边的元素都 ≥2；真正的第一个仍可能是下标 2，也可能更靠左。

因此记住 2 是右侧已经满足条件的边界，接着只检查它左边尚未判断的位置。我们没有否定 2 作为最终答案的可能性。

另一种情况也试试：若中间值是 1，而目标还是 2，那么它左边的数会不会够大？

检查另一半的理由

不会。数组有序，左边的数至多等于中间值 1，全部小于 2。中间位置自身也不满足条件，所以可以一起排除，接下来从 mid + 1 往右找。

二分的依据：有序性让一次比较证明一整段位置的性质。输入必须已经有序；这里只做搜索，不把排序算作这一步。

03 · 用两个边界记录刚才的理由

lo 和 hi 分别记录了什么？

我们用 lo、hi 记录“哪部分已经判断完了”。开始时 lo = 0、hi = n，还没排除任何元素。

  • lo 左边：已经确定全部小于 x。
  • hi 起向右：已经确定全部大于或等于 x。
  • lo 到 hi 之前：还需要继续判断。

第三段写成 [lo, hi)：左边包含 lo，右边不包含 hi，叫半开区间。例如 [0,2) 只包含下标 0、1。

容易混淆的一点：hi 不在“待判断的元素”中，但 hi 仍可能是最终答案。比如 hi=2，只表示下标 2 起已经够大，还需要判断 0、1 是否有更早的答案。

中间太小 → lo = mid + 1
中间够大 → hi = mid

中间下标取 mid = lo + (hi−lo) // 2，其中 // 2 表示除以 2 后向下取整。只有 lo < hi 时才取中间位置，所以一定有 lo ≤ mid < hi ≤ n，不会读到 a[n]。

现在你来走三步

默认仍是刚才的数组和 x=2。每次点击前，先预测下一步该改 lo 还是 hi，再看解释。走完后换一个边界例子。

查看已经走过的步骤

    刚才一直守住的两条事实——“lo 左边太小，hi 起已经够大”——就叫循环不变量（loop invariant）：每轮开始时都成立的事实。先理解这句话，再记术语。

    04 · 为什么停下来时答案就在这里？

    lo = hi 时，分界线已经确定

    对于 x=2，最后得到 lo = hi = 1。此时待判断区间 [1,1) 为空，1 左边都小于 2，从 1 起都大于或等于 2，所以 1 正是第一个满足条件的位置。

    每次更新都会让 hi−lo 严格变小，因此循环能够结束。如果最后 lo=hi=n，就说明所有元素都太小，按约定返回 n。

    如果 a[mid] = x，为什么用 hi = mid？

    想把理由写严谨：初始化、保持、结束

    初始化：lo=0、hi=n，两边已判断区域都没有元素，因此“左边都太小、右边都够大”成立，且 0≤lo≤hi≤n。

    保持：若 a[mid]<x，有序性保证直到 mid 都小于 x，令 lo=mid+1。否则有序性保证从 mid 起都≥x，令 hi=mid。两种更新都保留两条事实和边界顺序。

    终止：循环中 lo≤mid<hi，所以更新 lo 时它至少增加 1，更新 hi 时它至少减少 1。非负整数 hi−lo 严格减小，最终 lo=hi。

    答案：结束后，所有合法下标 i<lo 都有 a[i]<x；所有 lo≤i<n 都有 a[i]≥x。因此 lo<n 时它就是第一个满足条件的位置；lo=n 时不存在满足条件的元素。空数组开始就 lo=hi=0，直接返回 0。

    为什么它快？先看“每次至多一半”

    记待判断元素数为 w=hi−lo。取中点后，无论往哪边更新，新宽度都至多为向下取整的 w/2。本例从 5 → 2 → 1 → 0，只比较了 3 次。

    例如一百万个元素，最多比较 20 次即可确定这个边界。这种规模越大、比较次数增长越慢的关系叫对数增长；对 n≥2，时间上界写成 O(log n)，额外空间是 O(1)。渐进符号会在第二课开始逐步解释，这里先理解减半过程。

    05 · 把已经理解的规则写出来

    先读一遍，再补两行

    下面是完整 C++ 函数。a 是已排序数组，x 是目标值；函数返回下标，返回数组长度时表示没有满足条件的元素。读到两条更新时，试着用刚才的理由解释它们。

    int lowerBound(const vector<int>& a, int x) {
    int lo = 0, hi = static_cast<int>(a.size());
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < x)
            lo = mid + 1;
        else
            hi = mid;
    }
    return lo;
}
    用 Python 学：同一个算法 
    def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

    C++ 中，这里的非负整数除法自动向下取整；Python 用 //。len(a) 与 a.size() 都是在取数组长度。

    06 · 换个目标，自己走一次
    
    
    数组里没有 3，应该返回什么？
    
    
    仍用 [1,2,2,4,7]，把目标改为 x=3。先不点演示，写下每轮开始时的 (lo,hi)，并用一句话说明最终返回的位置为什么对。
    
    
    写完后核对
    (0,5)：mid=2，a[2]=2<3 → lo=3。
    (3,5)：mid=4，a[4]=7≥3 → hi=4。
    (3,4)：mid=3，a[3]=4≥3 → hi=3。
    lo=hi=3，返回下标 3。它的值是 4，是第一个≥3的元素；任务并不要求数组里恰好有一个 3。
    
    
    可选进阶：改成第一个严格大于 x
      
    这是 upper_bound。先用同一个数组、x=2 判断：应该返回下标 3。想一想，“中间值等于 x”这次应该被放在哪一边？
    
      
    想过后再看提示
    等于 x 还不够，应该与“小于 x”一起排除。因此把条件改成 a[mid] ≤ x 时令 lo=mid+1，否则令 hi=mid。不变量相应变成“lo 左边都≤x，hi 起都>x”。理解本课主线后再练这一题即可。
