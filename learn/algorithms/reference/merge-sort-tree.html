Reference · Merge Sort

递归树的三本账

单节点自身工作 → 同层工作 → 全树工作。不要重复计算子递归。

算法与正确性

长度≤1 直接返回；否则均分，递归排好两半，用 merge 合并。每次规模严格下降，所以终止。按长度归纳：两子结果有序且不丢元素；每次取两队首中较小者，便保留有序输出前缀，最终得到原元素的有序排列。

总长 m 的 merge 恰好写入 m 个元素，时间 Θ(m)；指针只前进，不用逐对枚举。相等取左边。模型：比较、索引、元素操作为常数；切片、复制按长度计。

n=2ᵏ：完整合并层

深度 d=0,…,k−1：2ᵈ 个规模 n/2ᵈ 的子问题，合并写入合计 n。深度 k：n 个单元素叶子，无 merge，另有 Θ(n) 边界开销。

W(n)=n log₂n；T(n)=Θ(W(n)+n)=Θ(n log n)

n=8：合并写入 8+8+8=24；包含叶子的总层数是 4，合并层数是 3。

任意 n≥2：把下界补全

令 h=⌊log₂n⌋、H=⌈log₂n⌉。最大深度 H；每层待合并区间长度之和≤n，而深度 0,…,h−1 全是合并节点、每层恰好 n。

n⌊log₂n⌋ ≤ W(n) ≤ n⌈log₂n⌉
½n log₂n ≤ W(n) ≤ 2n log₂n

最后一个合并层可能不满：n=5 为 5+5+2=12，不能说所有层恰好 n。n≥1 的调用数为 2n−1；局部切分、合并、复制均线性，故 T=Θ(W+n)。n=0、1 时 W=0，但 T=Θ(1)。

迁移检查与常见误区

  • 树的层次是记账分组，不是实际执行先后；merge 要等两子调用返回。
  • 节点收费只算自身 merge，不把递归子时间重复加入每层。
  • 普通版本有序输入也照常合并；不要混入提前跳过的优化。
  • 若改为 1 与 m−1：写入 n+(n−1)+⋯+2=n(n+1)/2−1=Θ(n²)；问题在于深度变为线性。

峰值空间与累计工作是两件事

本课复制数组、依次递归的实现，峰值辅助空间 Θ(n)，调用栈自身 Θ(log n)。一次活跃路径上的数组规模形成几何和；根合并同时保留左右临时结果，提供线性下界。前提是不再需要的数据可回收；讨论逻辑峰值而非运行时 RSS。

总 merge 写入 Θ(n log n) 是跨时间的累计量，不是同时保留全部历史数组。图示为对照保留节点快照，也不代表排序代码的峰值内存。相等时取左边可保持相同键值的原先顺序（稳定性）。
