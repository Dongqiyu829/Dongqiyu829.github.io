ETH 可能被推翻？

一个“算法不能快到什么程度”的猜想受到挑战。先理解这句话在比较什么，再读新闻标题。

前沿研究，独立验证中。

题目：The Exponential Time Hypothesis is False；署名 OpenAI。首次官方公布 2026-10-26；原稿标注 10-17、修订 10-25。最近核查 2026-10-27。OpenAI 报告 Lean 验证并安排外部审查；本站未重建 Lean 验证，也不把该主张写成已获学界确认的定理。

本篇目标：分清“主张的时间界”“形式化覆盖范围”“还需什么证据”。现在可读，深入建议在 NP 完全性与归约之后；不计课程进度。

1 · 先给三个开关找一种合法设置

x、y、z 各为真或假。∨ 是“或”，∧ 是“且”，¬x 是 x 的相反值。一个子句是几个文字（变量或其否定）的“或”；CNF 要求所有子句同时成立。3-SAT 问每个子句至多三个文字时，是否存在满足整个公式的赋值。

F=(x∨y∨z) ∧ (¬x∨y∨z) ∧ (x∨¬y∨¬z)

先试 x=0、y=0、z=1：三句都真吗？如果要数出所有答案，怎样确保不漏？

恰有 5 个满足赋值。SAT 只问计数是否大于 0；精确计数还要给出这个 5。后者有解就能决定前者。

n 个变量有 2ⁿ 种赋值。逐个验证给出 O(2ⁿ·poly(n+m)) 的暴力上界，m 为子句数；这只是一个算法上界，不能因此证明任何算法都必须这样慢。

2 · ETH、SETH 在猜什么？

ETH（指数时间假说）的常用说法是：3-SAT 不存在以变量数 n 为参数、时间为 2^{o(n)}·poly(输入长度) 的算法。这里讨论确定性版本；随机化版本另需说明。它是猜想，不是由 NP 完全性直接证明的事实。

SETH（强指数时间假说）更强：对每个固定 ε∈(0,1)，存在一个固定宽度 k，使 k-SAT 不能在 2^{(1−ε)n}·poly(输入长度) 时间求解。k 随 ε 选择，但算法运行中保持固定。SETH 蕴含 ETH（需要稀疏化等理论），不能只靠名称判断方向。

g(n)=o(n) 表示 g(n)/n→0。因而 2^{√n}、2^{n/√log n} 是以 n 为参数的亚指数；1.9ⁿ=2^{(log₂1.9)n} 虽然比 2ⁿ 快，仍是指数。多项式 nᶜ=2^{c log₂n} 也属于亚指数，但反过来不成立。

为什么 2^{√n} 不是多项式？

对任意固定 c，√n / log₂n→∞，所以最终 2^{√n}>nᶜ。因此“亚指数”允许比所有多项式都慢的增长。固定有限 n 的速度比较不能代替这些渐进关系。

基础参考：MIT Fine-Grained Complexity：ETH / SETH 与稀疏化。

3 · 新主张究竟降低了什么？

自然语言稿声称：对每个固定 k≥2，确定性算法能精确计算 n 变量、m 子句的 k-CNF 满足赋值数，并使用多项式空间。不是只把 2 的底数换成另一个固定数，而是声称指数中的因子会随 n 趋于 0。

下面只列本篇读到的范围，不尝试证明整篇新论文。对数在充分大的 n 上解释；O 下标允许常数依赖 k 或固定密度 D，不允许依赖 n。

证据层时间上界（发布方陈述）
10-25 自然语言稿，定理 1.1(n+m)^{O_k(1)} · 2^{O_k(n log log n / √log n)}
自然语言稿：m≤Dn，固定 D>0(n+m)^{O_{k,D}(1)} · 2^{O_{k,D}(n / √log n)}
Lean 范围文档 378.md(L+1)^{O_k(1)} · 2^{O_k(n (log log n)² / √log n)}

L 是规范编码的位长度。Lean 范围说明覆盖规范输入上的确定性精确计数与 SAT，且每个执行前缀访问的磁带单元总数为 L 的多项式。自然语言稿有更尖锐的界，不能声称这两条更强上界已由该 Lean 范围说明一并覆盖。

三条指数的增长均为 o(n)：例如令 t=log n，则 (log t)²/√t→0。这解释了发布方为何称其为亚指数反例。对固定 k，去重后的不同子句数量为 n 的多项式，编码可多项式控制；仍须核查普通输入到规范输入的转换与预处理成本，不能随意丢掉 poly(L) 因子。

4 · 这不等于 P=NP，也不会自动产生所有快算法

P 是可在多项式时间求解的判定问题；NP 是给出候选证书后可在多项式时间验证的问题。3-SAT 是 NP 完全问题：若它有多项式算法，则 P=NP；“NP 完全”本身并没有证明它不存在快算法。

3-SAT 的亚指数算法仍可超多项式，因此本主张即使成立，也不能据此宣布 P=NP。固定宽度 k 的结果也不能不加分析就套到 k 随输入增长的任意 CNF；更不能假定常数小、现在就能实用。

普通多项式归约可能扩大变量规模。假如 n 变量被变成 N=n² 的新输入，后者一个 2^{√N} 算法，对原参数仍需 2ⁿ。归约是多项式，不代表它保留亚指数。

5 · Set Cover 的条件下界会怎样？

Set Cover 给一个元素全集和若干集合，问能否选不超过预算数量的集合覆盖全部元素。例如全集 {a,b,c}、集合 {a,b}、{b,c}、{a}，预算 2 时可以覆盖。

某条下界证明若形式为“假设 ETH，则不存在指定参数下的快 Set Cover 算法”，一旦 ETH 的反例获确认，这条假设就不能再作为该困难性的依据。逻辑上的条件证明本身不会因此变成一篇推理错误的证明；它的前提失效，也不自动证明 Set Cover 已有同样快的算法。

必须逐条检查参数、归约方向、假说种类。NP 困难性、基于 P≠NP 的近似困难性、基于 ETH/SETH 或独立 Set Cover 假说的精细下界，并非一回事。Cygan 等《On Problems as Hard as CNFSAT》还区分了 Set Cover 的相关猜想与其他 SETH 等价问题；不能把所有 Set Cover 下界都标成 ETH 的直接推论。具体论文逐篇复核留作后续专题。

独立小问题：快算法是否沿归约传递？

归约把 n 变量公式变成规模 N=n² 的问题，并得到 2^{√N} 时间算法。请用原参数写出时间，解释它是否足以成为 ETH 的亚指数反例。

不自动判分、保存或同步，需反馈请自行复制。

提示

把 √N 中的 N 换回 n²；n 是非负规模。不能只看“亚指数”这个标签。

写完核对

2^{√(n²)}=2ⁿ，加上归约成本仍是以 n 为参数的指数上界，不能由此得到 2^{o(n)}。这不证明不存在更快算法，只说明给定推导不够。
