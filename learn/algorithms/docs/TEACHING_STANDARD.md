# 算法短课设计与维护规范

适用：HKUST COMP3711H 学习工作区；HKUST 课程为主，UMD 等教材为补充。每课默认主线 15–25 分钟，只设一个可以观察的学习成果。以下是规范，不是对学习者掌握情况的判断。

## 固定教学骨架

1. 一个具体问题；先明确输入、输出和必要前提。
2. 学生先预测、提出做法或尝试一个小例子。
3. 同一例子贯穿概念与直觉，术语在需要时引入。
4. 完整推导；严格证明可折叠，但必须交代假设、边界与结论。
5. 至少一道独立迁移题，要求推导、构造反例或解释安全性。
6. 一句总结、可选挑战，以及“不看答案能完成吗”的自检。

核心理解、严格证明、可选挑战在同一页分层展示，不复制成三套讲义。答案默认折叠；所有课程自由访问，完成标记和自检均不参与解锁。

## 三种互动不能互相替代

- 探索：改变输入、逐步观察过程，例如边界演示和逐轮柱图。
- 预测：在揭示结果前先计算或选择，错误反馈解释具体误区。
- 迁移：新边界、错误算法或新条件下，独立写出论证。选择正确或点完演示不等于掌握。

开放回答采用“独立输入 → 可选提示 → 参考解 → 自行复制给教师”。不使用字符串匹配冒充数学语义批改，不自动上传回答，不暗示与 ChatGPT 同步。只有实际回答、推导或实现能作为后续 learning-record 的证据。

## 常见误区检查表

| 主题 | 要检查的误区 | 反馈应指向 |
|---|---|---|
| 二分 | 找到任意相等值就返回 | “第一个”的输出契约与重复值反例 |
| 二分 | hi 不在待判断区，所以不可能是答案 | 元素区间 [lo,hi) 与答案边界 [lo,hi] 的区别 |
| 二分 | 把 hi=mid−1 搬进当前模板 | 哪条不变量被破坏；[1,2]、x=2 的反例 |
| 分析 | 两层循环必为二次 | 各轮实际工作量的和 |
| 分析 | 只有 O 就声称 Θ | 缺少匹配下界；常数必须独立于 n |
| 倍增 | 所有 n 都能写 W=2n−1 | 最后一轮 M 不一定是 n，M≤n<2M |
| 倍增 | 轮数乘最大轮必然紧确 | 较松上界与实际几何和的区别 |
| 递归树 | 在节点处再次计入整个子递归 | 节点只计自身合并，子节点另收费 |
| 递归树 | 任意 n 的所有合并层都恰好 n | n=5 最后合并层只有 2 次写入；用完整层给下界 |
| 递归树 | 叶子没有 merge，所以没有时间 | 单元素叶子有常数开销，合计 Θ(n) |
| 递归树 | 原始子数组已经是递归返回值 | Split 只拆原始输入；Merge 显示左右有序返回，再合并到父节点 |
| 空间 | 把所有历史写入当成同时保留 | 活跃数组的几何和；累计工作与峰值空间分开，图示缓存不当成程序内存 |
| 分治 | 递归就一定 n log n | 1 与 m−1 拆分的树高为线性，重新求和 |

每道错误选项都应有针对性解释，不只写“错了”。选项长度和格式尽量一致，不靠外观泄露答案。

## 课程元数据与本地进度

- `assets/course-manifest.json` 是已发布课程、规划主题数、资源 release 的唯一维护入口。一个 topicId 可对应多个课时页面；published=false 的页面不计入个人完成分母。
- 继续使用旧键 `comp3711h-learning-progress-v1`，保留有效旧记录与暂未识别的字符串 ID；显示时只统计已发布 ID 的交集，并去重。
- 存储读写失败或格式异常时，临时记录在当前页面，清楚告知刷新后可能丢失；不因此中断 Quiz 或其他互动。
- 完成记录不是掌握记录，不跨浏览器/设备同步。开放回答和自检不自动保存到进度。

## 编辑器：可观察状态与离线退路

- 所有编程课统一复用 `assets/compiler-lab.js`；第一、三、四课起始代码分别在 `binary-programs.json`、`doubling-programs.json` 与 `merge-programs.json`。第四课编码可选，不挤占 20–25 分钟主要路径。
- `populateCode` 仅是请求。启用 `codeChangeEvent=true`，只接受来自当前 iframe、正确服务 origin、相同语言且内容匹配的代码回传，才显示“确认载入”。它不证明代码正确或测试通过。
- 初次发送后不因用户编辑而自动重新填入；语言切换创建新 frame，旧 frame 的消息不能确认新状态。
- 手机端第三方工具栏可能挤出内置 Run；课程页另设“运行当前编辑区代码”，使用官方 triggerRun 接口。仅在起始代码已确认载入后启用，按钮不判断测试是否通过。
- 未收到确认时显示超时／未确认提示，提供重填、重载、独立页面、完整代码复制。不能一直锁住界面，也不能伪报成功。
- 完整 C++、Python 起始代码与全部测试直接包含在 HTML 中；第三方失败、JSON 请求失败、JavaScript 禁用时仍可手动复制。
- 不尝试跨域读取服务内部状态；运行验收以真实编辑器操作和控制台结果为准。第三方服务不可用时，必须标记“未执行／受阻”，不能把本地或 mock 测试算成在线通过。

## 缓存与零构建维护

1. 先读取当前 GitHub HEAD 和待修改文件，保留并发变更。
2. 修改源 HTML、组件或程序 JSON；更新 manifest 的 release。
3. 执行 `node scripts/prepare-site.cjs`。它只机械同步版本参数、页面内课程元数据、首页统计和静态代码副本，不打包、不引入网站运行依赖。
4. 执行 `node scripts/prepare-site.cjs --check`、`node scripts/check-site.cjs` 和浏览器验收。HTML 验证工具仅安装在 `work/quality` 中，版本固定。
5. 原子提交 tree/commit，再带 expected SHA 快进 main；如果 HEAD 变化，重新读取并合并，不能强行覆盖。
6. 等 GitHub Pages 部署成功，核验公开页面。GitHub Pages 对 HTML 的缓存仍受平台控制；统一版本保证新页面所引用的资源来自同一 release，不承诺所有已打开的旧标签页立即刷新。

验收依赖只属于开发工具。新环境可在 scripts 目录安装 package.json 中固定的 devDependencies；默认浏览器为 Edge，可用 COURSE_BROWSER_CHANNEL 指定其他已安装渠道，CXX / COURSE_PYTHON 可指定编译器和解释器。测试产物写入本地 work/qa，不作为课程内容发布。

## 最低验收矩阵

- 所有公开 HTML：标准静态校验、重复 ID、有效嵌套、资源和锚点、统一 release、代码副本一致。
- 桌面 1280px、手机 390px / 320px：阅读、导航、预测与探索、开放输入、失败回退。至少一次检查参考卡打印布局。
- 进度：旧记录、重复/未知 ID、非数组/损坏 JSON、存储读取拒绝、写入配额失败、发布课时与规划主题分离。
- 编译器：所有编程课 × C++/Python 的真实初载、切换、填入、运行；模拟无回传、阻断服务、旧消息、重载和刷新。模拟与真实测试分别列出；COURSE_EDITOR_LESSON 可限定单课，须标明验收范围。
- 无 JavaScript：核心知识、原生折叠参考和两种语言完整代码仍可读；无解锁限制。
- 报告列出通过、失败、未执行、第三方限制；不把历史验收当作本轮实测。
